# 雀魂策略助手 · 桌面版 v1.8.0

本版包括全屏定位、可保存设置、迷你模式、中文牌名、先初判后详解、逐家场面分析和副露核算。[最新交付说明](docs/交付说明-v1.8.0.md)；[策略依据](docs/策略依据与限制.md)。旧 [项目交接文档](项目交接文档.md) 对应 v1.3.0 基线。

## 启动

双击 `启动.cmd` 或 `启动-v1.8.0.cmd`，也可运行 `dist-v1.8.0\MahjongStrategyAssistant\MahjongStrategyAssistant.exe`。保留 `MahjongStrategyAssistant` 整个文件夹及其中 `_internal`，无需另装 Node.js 或 Python。旧发布目录继续保留。

首次换电脑或 Windows 账户，需在“模型与截图设置”重新填写模型地址与密钥。密钥用当前用户 DPAPI 加密保存，不在源码或 EXE 中。

## 使用

- 主按钮“截图并分析策略”：自动抓取雀魂原生客户端窗口并分析。
- **菜单“自动分析牌面变化”**：可选开启。仅通过截图监测手牌区与中央牌河的稳定变化，变化后自动给出建议，8 秒冷却；可随时关闭。只在“雀魂窗口”截图来源下生效。
- “模型与截图设置”可切换截图来源（雀魂窗口／全屏）与分析模式。
- 设置内容可滚动，底部固定显示“保存设置”和“取消”；F6 打开设置，Ctrl+S 保存，Esc 取消。修改后需保存才会生效。默认文件不可写时先尝试当前账户配置，再尝试 EXE 旁的 `user-data/settings.json`；三处都不可写则明确提示失败并保留原设置。密钥始终用 DPAPI 加密，重启读取最近保存的配置。
- “视图 → 迷你模式”或 F8 在完整窗口和迷你窗口之间切换。迷你窗口保留截图、取消、设置、展开和攻守摘要，可在视图菜单关闭置顶；窗口偏好随配置保存。Ctrl+, 打开设置。
- “文件 → 打开截图并分析”可直接分析已保存图片。无需手动框牌、标注模板或输入手牌。
- 全屏或导入桌面图在缺少窗口坐标时，会依据游戏区域和手牌行恢复牌桌位置；预览和模型使用同一份裁剪牌桌。没有足够视觉证据时仍可能无法定位，不保证任意皮肤和遮挡画面可识别。
- 先显示模型的初步建议，再自动补全具体场面分析。初判出现后可点“重新截图”停止旧分析并抓取新牌面；也可取消详解并保留初判。完成后可导出文字或 JSON。
- “关于”显示版本与数据来源说明。

## 三种分析模式

| 模式 | 端到端 | 说明 |
|---|---|---|
| **结构化（默认，推荐）** | 初判先显示，详解随后补全 | 两次简短思考请求串行。初判看整桌并给当前取舍；详解结合逐家牌河、副露、现物、宝牌、点棒、局数与备选条件。点棒按座位单独旋转放大，可靠手牌以本地核验为准 |
| 快速识图 | 约 9 秒 | 模型额外看一张压缩图辅助判断，思考 low |
| 完整 | 85–148 秒 | 两阶段串行：整桌视觉观察 + 深度策略，思考 low/medium |

三种模式都只输出可见信息下的参考建议；模型的内部推理正文不展示、不写入报告。

本轮有限样本初判约 2.45–7.27 秒，详解约 26.64–35.99 秒；最终两张图复验分别为初判 6.18 / 7.27 秒、完整 34.37 / 35.99 秒。多副露样图在优化前初判约 11.3 秒、完整约 39.1 秒，本地识别约 5.9 秒；优化后本地约 3.1–3.5 秒，相同像素再次处理约 0.7 秒。它们不是所有画面或服务负载下的保证，详解可随时停止。

## 当前工作方式

1. **本地识别**：OpenCV 找手牌行与牌面，随附图案模板比对；兼容赤五与粉色高亮。牌河、副露、宝牌指示牌为带置信度的本地候选。
2. **规则核算（程序）**：实际宝牌由指示牌换算；向听/进张由 V8 运行原网页已审查核心计算；物理牌数超过 4 张会在报告中标记“待核验”。
3. **模型决策**：接收可靠手牌、场面候选、不同路线的向听、可碰对子碰后的核算、整桌图与分座位点棒图。先初判，再给进攻、防守、备选、鸣牌与顺位计划；连接中断自动重试一次。候选和模型仍会误读，不会把低置信结果当成完整真值。

## 必须了解的限制

- **宝牌指示牌**由本地识别（含叶槽皮肤的面板兜底）并换算实际宝牌（荣誉牌两个独立循环：风牌東→南→西→北→東，三元牌白→發→中→白），作为事实传入。

- **支持副露（鸣牌）手牌，含各家副露候选**。每组面子按三张有效牌计算，杠按四张实体牌扣除可见牌。暗牌加面子有效总数为 13 张时等待摸牌，14 张时给打牌建议。区域识别和兜底无法确认的组保留未知，不把旋转、遮挡的牌强行命名；低置信牌河不进入已见牌扣除。副露普通型向听和进张由本地核算，成役、攻守与是否鸣牌交给模型结合全桌判断。
- **支持自定义分辨率**。窗口按实际客户区尺寸抓取，识别用相对比例定位，低分辨率会先归一化到参考宽度再匹配。实测 1280×700 至 3840×2100、不同宽高比、全屏截图下任意窗口偏移均可正确读牌。低于约 1200 像素宽时牌面细节不足，可能拒识，请放大游戏窗口。若游戏被遮挡或该渲染模式返回空白（v1.4.1 起），助手会自动改用全屏截图并按游戏客户区裁剪；若仍无法定位游戏窗口，会提示把雀魂窗口恢复并完整露出。远程桌面叠层可能影响抓取，需保证游戏在屏幕上可见。
- **仍会识别错**。模板相似分不是正确率；牌河、副露、风位可能误读。低置信信息不会被硬扣成确定枚数。
- **不是全知或最优策略引擎**。看不到对手暗牌和未来牌山；单帧不能完整还原摸切、临时振听、鸣牌先后。
- **副露普通型核算已补充**，包含向听和可见牌扣除后的进张。每组面子算三张有效牌，杠仍按四张实体扣牌。它不等于完整的役、符数、点数与振听核验；三麻未充分验证。
- **自动分析有冷却**，不适合毫秒级出牌决策；忙时发现新变化会排队停止旧分析，再处理新画面。
- **截图会发送到所配置的模型服务**，默认不将原图自动保存到磁盘。

## 开发与验证

```powershell
python -m pip install -r requirements-desktop.txt
python desktop_app.py
python -m PyInstaller desktop_app.spec
python _dev/test-desktop.py
npm test
```

测试入口：`_dev/test-desktop.py`、`_dev/test-window-fixes.py`、`_dev/test-strategy-v18.py`、`npm test`。设置 MJ_USER_FIXTURES 以覆盖两张旧私有样图，MJ_DESKTOP_FIXTURE 指向用户全屏样图。测试结果与 GUI 验收边界见最新交付说明。私有样图保存在项目外，不随应用分发。

自动识牌来源为 MIT 许可的 [majsoul-vision](https://github.com/sdtafxy/majsoul-vision)，版本与修改记录在 `auto_vision_vendor/SOURCE.json`；格式修复用 json-repair，JS 运行时用 mini-racer，图像处理用 OpenCV/Pillow/numpy。
