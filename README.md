# 雀魂策略助手 · 桌面版 v1.6.1

完整技术交接见 [项目交接文档](项目交接文档.md)。本版主要变化：默认结构化模式约 8 秒、自动分析、规则事实由程序核算。

## 启动

双击 `启动.cmd`，或运行 `dist\雀魂策略助手\雀魂策略助手.exe`。保留 `雀魂策略助手` 整个文件夹及其中 `_internal`，无需另装 Node.js 或 Python。

首次换电脑或 Windows 账户，需在“模型与截图设置”重新填写模型地址与密钥。密钥用当前用户 DPAPI 加密保存，不在源码或 EXE 中。

## 使用

- 主按钮“截图并分析策略”：自动抓取雀魂原生客户端窗口并分析。
- **菜单“自动分析牌面变化”**：可选开启。仅通过截图监测手牌区与中央牌河的稳定变化，变化后自动给出建议，8 秒冷却；可随时关闭。只在“雀魂窗口”截图来源下生效。
- “模型与截图设置”可切换截图来源（雀魂窗口／全屏）与分析模式。
- “文件 → 打开截图并分析”可直接分析已保存图片。无需手动框牌、标注模板或输入手牌。
- 分析过程中可取消；完成后可从文件菜单导出文字或 JSON 报告。
- “关于”显示版本与数据来源说明。

## 三种分析模式

| 模式 | 端到端 | 说明 |
|---|---|---|
| **结构化（默认，推荐）** | 约 10 秒 | 本地程序识别手牌/副露并核算规则（核验事实）；模型另收到一张压缩小图用于读牌河、立直、点棒、局数，手牌与副露以 JSON 为准。思考仍开启（low） |
| 快速识图 | 约 9 秒 | 模型额外看一张压缩图辅助判断，思考 low |
| 完整 | 85–148 秒 | 两阶段串行：整桌视觉观察 + 深度策略，思考 low/medium |

三种模式都只输出可见信息下的参考建议；模型的内部推理正文不展示、不写入报告。

## 当前工作方式

1. **本地识别**：OpenCV 找手牌行与牌面，随附图案模板比对；兼容赤五与粉色高亮。牌河、副露、宝牌指示牌为带置信度的本地候选。
2. **规则核算（程序）**：实际宝牌由指示牌换算；向听/进张由 V8 运行原网页已审查核心计算；物理牌数超过 4 张会在报告中标记“待核验”。
3. **模型决策**：接收结构化局面（手牌、副露、宝牌为本地核验事实）加一张压缩小图（供读牌河、立直、点棒、局数），不重算规则，不改写核验手牌；连接中断自动重试一次。

## 必须了解的限制

- **宝牌指示牌**由本地识别（含叶槽皮肤的面板兜底）并换算实际宝牌（荣誉牌两个独立循环：风牌東→南→西→北→東，三元牌白→發→中→白），作为事实传入。

- **支持副露（鸣牌）手牌，含各家副露**。暗牌加副露合计 13 张时等待摸牌，14 张时给打牌建议；本家与对家/上家/下家的副露由本地识别并传入结构化局面，模型据此判断役种、威胁与已见牌。本家/对家/上家/下家的副露都有区域级识别与兜底（碰/杠同种组自动补全牌名；本家吃牌在两端牌名可读时按连续性推断中间张，标记 inferred；对家倒置吃组以无名牌组呈现）。牌河低置信读数（<0.65）不再进入结构与物理核验，避免"白板"类模板噪声误触超编降级。；副露手牌没有门清向听核算，向听与打牌由模型结合副露推理。
- **支持自定义分辨率**。窗口按实际客户区尺寸抓取，识别用相对比例定位，低分辨率会先归一化到参考宽度再匹配。实测 1280×700 至 3840×2100、不同宽高比、全屏截图下任意窗口偏移均可正确读牌。低于约 1200 像素宽时牌面细节不足，可能拒识，请放大游戏窗口。若游戏被遮挡或该渲染模式返回空白（v1.4.1 起），助手会自动改用全屏截图并按游戏客户区裁剪；若仍无法定位游戏窗口，会提示把雀魂窗口恢复并完整露出。远程桌面叠层可能影响抓取，需保证游戏在屏幕上可见。
- **仍会识别错**。模板相似分不是正确率；牌河、副露、风位可能误读。低置信信息不会被硬扣成确定枚数。
- **不是全知或最优策略引擎**。看不到对手暗牌和未来牌山；单帧不能完整还原摸切、临时振听、鸣牌先后。
- **本地精确核算限于门清 13/14 张**。自家吃碰杠后无同等完整核算。三麻与非默认布局未充分验证。
- **自动分析有冷却**，不适合毫秒级出牌决策；忙时不会重复触发。
- **截图会发送到所配置的模型服务**，默认不将原图自动保存到磁盘。
