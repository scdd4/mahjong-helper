## 本版修的两个问题

你截图里那条 **"模型输出达到上限，请在模型设置中提高输出上限后重试"**，
根因不是设置不对，是代码给的预算本身就必然不够：

- 快速模式设了 `max_tokens=200`。
- Spark 服务端规定 **思考预算 = max_tokens 的一半**，也就是只有 100 token。
- 实测模型在真实牌局下思考要 183 字符，加起来用掉 **195 / 200** token。
- 于是稍有波动就 `finish_reason=length`，直接报错。这是概率性故障，
  所以表现为"时好时坏"。
- 加大上限并不能变快：600→9.84s、1024→10.52s，思考预算越大它想得越多。

第二个问题是慢。同一张真实截图实测：开思考 low 档 **10.85s**，关思考 **2.81s**。

## 做了哪些改动

| 改动 | 原因 |
|---|---|
| 关闭思考（`reasoning_effort=none`） | 既吃掉一半输出预算，又拖慢 4~5 倍 |
| 不再发送截图给模型 | 手牌已本地核验；无图 1.6s vs 带图 2.35s |
| 弃牌由本地求解器决定 | 0.09s 出结果，且杜绝模型报出不存在的牌 |
| 立直时安全牌优先 | 对家立直且有现物时，安全压过牌效率 |
| 已和牌 0 秒返回 | 程序直接给结论，不发请求 |
| `max_tokens` 200 → 512 | 不思考也要留足余量，远离上限 |
| 模板加载加缓存 + 启动预热 | 首次识别省掉一段固定开销 |
| 13 张理由显示"3向听，57张进张" | 原来是无意义的"未轮到你" |

弃牌正确性现在有双重保障：本地求解器给答案，模型只写理由；
模型若报出与本地不一致的牌，自动采用本地结果并在提示里说明。

## 什么时候该用结构化模式

快速模式**不看牌河**（不发图），只在本地手牌 + 立直安全牌上做判断。
以下情况请 F6 切到「结构化（初判+详解）」：

- 需要判断他家副露威胁、点棒状况、场况取舍
- 立直判断复杂（多家立直、需要精确危险度排序）
- 想看清楚为什么不打另一张

## 已知边界

- 立直检测为几何推测，面板显示"疑似立直(待复核)"，请结合立直棒确认。
- 单侧筋、字牌只是弱线索，不当绝对安全。
- 仅门清 13/14 张可本地核算；副露手牌核算为参考。
- 高难识别（四同牌、多赤五、字牌密集）落入置信灰区会被安全拒绝并指出牌位。
