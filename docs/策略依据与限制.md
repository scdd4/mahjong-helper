# 策略依据与本轮改进

更新时间：2026-11-20。对应桌面版 v1.8.0。

本轮通过阅读公开麻将程序、整理决策框架、补充可核算事实，再让 Spark 思考的方式改进策略。没有训练或微调模型权重；最终取舍仍由开启思考的 Spark 生成。

## 实际参考的资料

1. [MahjongRepository/tenhou-python-bot：防守与攻守界限](https://github.com/MahjongRepository/tenhou-python-bot/blob/dev/project/game/ai/defence/main.py)。参考其按对手分别评估风险，再结合自身向听、等待宽度、自身价值、对手预估价值和顺位调整攻守的思路。没有照搬固定阈值来直接决定用户出哪张牌。
2. [同项目的对手威胁分析](https://github.com/MahjongRepository/tenhou-python-bot/blob/dev/project/game/ai/defence/enemy_analyzer.py)。参考其结合立直、庄家、副露、公开役和宝牌等识别威胁，而非把“有副露”等同于“已经听牌”。
3. [MahjongRepository/mahjong](https://github.com/MahjongRepository/mahjong) 及其 [向听实现](https://github.com/MahjongRepository/mahjong/blob/master/mahjong/shanten.py)。项目固定引入 MIT 许可的 mahjong 2.2.0，只用于补充副露手牌普通型向听/进张核算。原门清 JS 核算继续保留。上游大规模验证数据不等于本应用已经完成同等验证。

## 当前模型得到的证据

- 本地核验手牌及普通型、七对子、国士的向听参照。
- 四家牌河和副露候选，以及按玩家分开的现物、筋等有限风险线索。
- 指示牌换算后的实际宝牌。
- 完整牌桌图，以及按自己、下家、对家、上家旋转和标注的点棒拼图、本家风位放大。
- 有效张数与杠的区别、搭子形状、可碰对子在假设鸣牌后的向听参照。
- 最近几次策略摘要。它不是完整牌谱，无法可靠还原所有摸切、临时振听或鸣牌顺序。

初判先返回行动和关键理由，随后自动补充攻守、备选、鸣牌条件、点差与逐家威胁。两次请求串行、都开启思考；新截图可以取消旧详解。

## 保证事实与保留不确定性

现物必须对应具体玩家；对一家安全不代表对其他家安全。筋和字牌不能当成绝对安全牌，三元牌始终可能成为役牌。

杠是四张实体牌，但面子只算三张有效牌；自己摸到牌不能直接称为“碰”，碰牌要求他家打出。程序会纠正部分明显的操作时机用语，并显示规则核对说明；原始最终回答保留在结构化结果中用于复盘。

进一步核对一向听不能立直、碰白发中不会失去役牌、碰普通数牌本身不提供役牌；分别核算普通型和七对子路线。顺位和距前一档的点差依据本轮读取的四家点棒重算，但点棒读数本身仍可能出错。这些核验没有替模型决定进攻还是防守。

本应用不能保证模型正确理解每张旋转或遮挡的牌，也不能保证策略最优。点棒拼图依赖常见客户端布局；模糊或布局偏离时仍可能误读。副露普通型核算不等于完整的役、符数、点数和振听裁判。

最终两张图的真实服务复验中，模型能够结合七对子、逐家副露和点差，但仍出现“备选弃牌会退向听”的理由与本地核算不一致、后续退守提出当前手里没有的字牌等问题。现有核验只能覆盖部分明确矛盾，不构成完整策略正确性证明；应以本地核算面板核对数值，牌面变化后重新截图。

策略场景集已修正若干标注与评分问题，包括多家立直不能合并成全局安全并集、建议牌必须在手中，以及打点题的理由检查。新口径不能直接与原有 16/24 基线相比，也不能换算为实战胜率。
