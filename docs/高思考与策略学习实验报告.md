# 高思考 / 策略学习 提分实验报告

日期：2026-11-21。针对"能否开高思考、能否学习优秀策略提高准确度"的实测结论。

## 结论先行

**在 Jev 受限决策范式（只输出一张牌）下，高思考和学习规则都不能实质提高准确度：**

| 配置 | 59 场景准确率 | 延迟 | 结论 |
|---|---|---|---|
| 当前 Jev（关思考） | **81%**（48/59） | 1.21s | 基线 |
| 关思考 + 策略规则注入 | 80%（47/59） | 1.48s | **更差** |
| **高思考 + 策略规则** | **83%**（49/59） | **11.59s** | +2 点，但慢 10 倍 |

高思考全量只多对 1 题，代价是每局从 1.2s 变成 11.6s。不值得。

## 为什么和历史 A/B 结论不同

历史 A/B 研究（47 题）结论是"开思考 91% vs 关思考 79%，必须保持思考"。那个实验用的是**完整 JSON 契约**——模型要输出 stance/reason/offense/defense 等大段分析。

思考的收益主要体现在**攻守论述和理由质量**上，而不是"最终打哪张牌"。当 Jev 把答案空间锁死到单个 token 时：
- 思考过程无法改变输出格式，只能在候选间做更精细的选择
- 实测这个"更精细"只值 2 个百分点

**关键洞察**：用户要的是"只告诉我打什么牌"，而这个任务上，受限候选 + 完整事实注入（现物/筋/宝牌/进张）已经榨干了大部分可提升空间。思考预算花在了用户看不见、也不需要的地方。

## 分类别数据（高思考 vs 关思考）

定向实验（11 道 medium/low 错题 + 2 道对照）：

| 配置 | 攻守难题 |
|---|---|
| 当前 Jev | 2/13 (15%) |
| 关思考 + 规则 | 5/13 (38%) |
| 高思考 + 规则 | 6/13 (46%) |

攻守类确实是高思考唯一有收益的地方（+4 题），但：
1. 全量口径下这一点收益被其他类别的波动抵消（83% vs 81%）
2. 攻守题的样本本身小（10 题），单题波动就是 10 个百分点
3. 11.6s 的延迟对实战不可接受

## 关于"学习优秀策略"（微调模型）

服务器条件（10.201.137.10，SSH user/405405）：
- NVIDIA GB10 GPU + 121G 内存 + 3.7T 磁盘
- `thenv` 环境有 torch 2.11.0+cu128，CUDA 可用
- **但缺 transformers / peft / trl / datasets，pip 源探测超时（外网不通）**
- 模型是 GGUF 量化格式（79G），微调需要 HF 原权重（不存在）
- 无任何训练数据（无 jsonl/parquet）

**微调路径在当前环境不可行**：装不了训练库、没有原权重、没有训练数据。即使能，微调一个 79G 模型用于"选一张牌"的任务，投入产出极差——ExactSolver 已经把牌效率算到最优，模型真正要补的只是攻守权衡，那靠规则/事实注入更直接。

## 最终建议

1. **保持当前 Jev 配置**（关思考 + 受限候选 + 事实注入），81% / 1.2s 是速度与准确度的最佳平衡点。
2. **若追求极致准确度**：用现有的 `structured` 模式（2 次请求、开思考、输出完整分析），历史 47 题 91%。代价是 5-8s 和大段文字——与"只要打什么牌"的诉求冲突。
3. **不建议**：为 Jev 开高思考（+2 点换 10 倍延迟）、注入抽象规则（反而 -1 点）、微调模型（环境不支持）。
