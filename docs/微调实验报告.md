# 麻将大模型微调实验报告

日期：2026-11-22。两步走全量微调（Qwen3.8-4B → Qwen3.8-27B），检验能否超越当前 Jev 决策方案（81% / 1.24s）。

## 结论先行

**未超越基线，且两个微调模型都更差。维持当前 Jev 方案，不将微调模型投入生产。**

| 方案 | 59 场景准确率 | 中位延迟 | 幻觉率 | 结论 |
|---|---|---|---|---|
| 当前 Jev（关思考） | **81%**（48/59） | 1.24s | 0% | **基线，保留** |
| 4B 全量微调 | 71%（42/59） | 0.95s | 0% | −10 点，未达标 |
| 27B 全量微调 | 49%（29/59） | 5.03s | 0% | −32 点，明显更差 |

27B 参数量为 4B 的 6.75 倍，但准确率反而从 71% 掉到 49%、延迟慢 5.3 倍。增大参数量未补上短板，反而拖累了牌效率判断。

## 分类准确率对比

| 类别（题数） | Jev 基线 | 4B 微调 | 27B 微调 |
|---|---|---|---|
| efficiency 效率（21） | **100%** | **100%** | 62% |
| defense 防守（21） | **90%** | 81% | 71% |
| push_fold 攻守（10） | 30% | 30% | 10% |
| value 打点（7） | **71%** | 14% | 0% |

关键观察：
- **效率题**：4B 与基线并列满分，但 27B 掉到 62%（丢 8 题）。这是 27B 总分的
  主要失血点，说明大模型并未更稳地学会计牌/进张判断。
- **打点题**：两代微调全面崩溃（14% → 0%），基线为 71%。训练数据里 value 类
  理由是模板文案（"保留宝牌役牌打浮牌"），没有教会具体打点计算，模型只记住了话术。
- **攻守题**：三方都不超过 30%，是基准本身的难点，微调无改善。
- 27B 的回复里反复出现同一句模板理由（"保留宝牌役牌打浮牌"/"保留宝牌役牌打共同安全"），
  与场景无关，属于典型的"背文案而非学决策"。

## 数据方案有效性评估

数据侧（41503 条，ExactSolver + 安全规则生成答案）对**纯效率判断**有效：
4B 在 efficiency 上达到 100%，证明"求解器候选 + 微调"能让小模型学会进张取舍。

但对需要推理的类别（value / push_fold）无效，根因在数据结构：
1. 理由字段是模板化文案，缺少打点计算、攻守取舍的推导过程，模型学不到推理链；
2. 答案空间被压成单张牌，缺失 stance/攻守标签等监督信号，攻守题无从学习；
3. 空思考块（`<think></think>`）虽修复了格式，但也切断了思考带来的推理增益——
   此前"高思考实验"已证明在受限输出下思考仅值 +2 点，此处连这点也没有了。

**结论**：当前数据配方只适合训练效率型子任务，不足以支撑完整决策模型。

## 训练中修复的问题

1. **assistant_only_loss 缺失**（第一版）：模型只学会复述 prompt。改为对话式数据集 +
   `assistant_only_loss=True` + 答案前显式空思考块后，格式修复成功，输出稳定为 `牌名|理由`。
2. **训练/验证拆分**：41503 条拆为训练 37352 + 验证 4151，避免过拟合评估集。
3. **断点续传下载**：27B 模型 18 分片断点续传，本机只做中转，暂存随传随删（当前暂存为空）。
4. **27B meta tensor 兼容**：`fix_untrained_tokens` 遇 device_map 懒加载的 meta tensor 报
   `Cannot copy out of meta tensor`，已在训练脚本开头 monkeypatch 禁用，patch 生效。
5. **评测解析 bug**：`eval_server.py` 的 discard 字段解析错误（skip_special_tokens 剥掉
   think 尖括号，得到 `<think>`），reply 字段完整。已用 `rescore_eval.py` 从 reply 重新提取牌名，
   并用独立严格解析复核，两者评分一致（27B 29/59、4B 42/59）。
